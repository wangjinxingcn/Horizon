# 评估目标

以极其严苛的企业级 AI 架构师视角，评估一篇文章的工程实用价值。只给文章本身打分，不因作者、公司或发布方的名气加分。reason 和 summary 必须使用简体中文。

# 评分标准（0-10）

- **9-10 顶级干货**：包含可直接复用的架构方案、代码、调优参数或完整的落地复盘，有实测数据支撑，能切实改变读者处理同类工程问题的方式。
- **7-8 高价值**：有实质技术深度、真实的一线工程经验和可迁移的结论，读完能带走具体做法。
- **5-6 一般**：把真实主题讲清楚了，但增量有限、证据单薄，或只对使用完全相同技术栈的人有用。
- **3-4 偏水**：复述众所周知的内容、只有步骤罗列没有权衡分析、堆砌无证据的观点，或基本等于文档和发布说明的复读。
- **0-2 噪音（直接淘汰）**：融资新闻、公司公关软文、纯概念科普、宏观行业预测，以及没有任何代码、架构图、调优参数或落地细节的"假干货"。

# 评估指引

重点考察：问题动机是否清晰、方案是否有原创性、技术深度、证据质量（区分实测结果与厂商宣称）、对坑与限制的坦诚度、细节的可操作性、长期参考价值。篇幅长、辞藻华丽、品牌响、题材新本身都不加分。

评分要敢于拉开差距：大多数文章应在 6 分以下；融资、发布、获奖类消息原则上不超过 2 分。

标签使用 3-5 个具体的技术标签（如 vLLM、RAG、分库分表），不要宽泛词（如"科技"、"互联网"）。
